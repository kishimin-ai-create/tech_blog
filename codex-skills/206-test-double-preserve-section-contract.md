# テスト用 API にもセクション変更の契約を持たせる

## 背景

管理画面からリンクの URL とセクションを編集するブラウザーテストを追加した。ブラウザーは実際の Hono 認証・管理ルートへ接続するが、保存処理はテスト用のメモリー実装に差し替えている。

## 起きたことと対応

テストではリンクを Engineering から Hobby へ移動し、保存後の一覧に Hobby と表示されることを期待した。最初は URL が更新されても Engineering のままとなり失敗した。調べると、テスト用 API が保存後のセクションに関係なく、リンクを常に Engineering の配列へ入れていた。

テスト用 API を、保存されたセクションに応じて Engineering または Hobby の配列へ返すよう変更した。認証状態とテストデータはログイン時に用意し直し、ブラウザー間で前の実行結果を引き継がない。

## 検証と限界

Chromium と WebKit でログイン・復元・ログアウト、未保存入力の警告、リンクの編集とセクション変更の計6件が成功した。Hono の HTTP ルートは実装を通るが、テスト用メモリー保存のため PostgreSQL の更新自体は検証していない。DB を使う API テストとは確認範囲が異なる。

## 学び

テストダブルは値を返すだけでなく、対象の振る舞いに必要な契約を保つ必要がある。特に更新後の再取得を検証するときは、入力値と一覧の分類が一致しているかを確認する。失敗をすぐ本番コードの不具合と決めず、ダブルと実装の境界も照合する。
