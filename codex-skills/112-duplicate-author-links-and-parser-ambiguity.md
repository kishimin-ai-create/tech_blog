# 同じ著者へのリンクが2個あると解析に失敗した理由

## 結論

今回の著者照合エラーは、著者名と一致するリンクがページ内に2個あり、パーサーが一致要素を1個だけ要求していたため発生した。2個の行き先URLは同じだった。取得失敗ではなく、取得成功後の著者リンク選択の失敗である。

原因は確認できたが、修正は実施していない。本記事は、HTMLパーサーを保守する読者向けの調査記録である。確認日は2026年10月15日、環境はWindows、Python 3.14.7である。

## 発生した問題

### 症状

```text
collection failure stage=record source=source_a exception=ParseContractError
```

同じ分類の例外が他の記事でも発生していたが、このログには個別の原因メッセージが出ていなかった。例外名だけで同一原因とは判断できなかった。

### 発生条件と影響

公式の記事一覧から詳細を取得する手動バックフィルで発生した。対象の未保存記事を再取得するとHTTP 200だった。タイトル、著者、日時、本文の各要素も存在したが、記事の保存には到達しなかった。

## 調査

取得ログに出た記事IDとDBの保存済みIDを比較し、対象メンバーの未保存記事を絞り込んだ。その詳細HTMLを、収集と同じ `SourceAdapter.parse_detail` へ入力した。

```text
entity link is missing or ambiguous
```

発生箇所は `_entity_link` の最終的な例外送出だった。画像URLの検証で失敗した別記事とは、同じ `ParseContractError` でも処理段階が異なる。

## 原因

`_entity_link` は設定されたセレクターでリンク候補を集め、著者名とテキストが一致するものを選ぶ。一致数が1個なら採用し、一致数が1個でなくても候補全体が1個なら採用する。それ以外は曖昧として拒否する。

実ページには、著者名と完全一致するリンクが2個存在した。候補全体は29個あり、どちらの単一要素条件も満たさなかった。両リンクの行き先は同じメンバーの記事一覧だった。

次は観測した構造を匿名化した説明例であり、実ページの転載ではない。

```html
<a class="author-link" href="/authors?entity=7">Example author</a>
<a class="author-link" href="/authors?entity=7">Example author</a>
```

DOM要素の数が複数であることと、リンク先の著者が複数であることは一致しない。今回の実装は前者の数で判定していた。

## 対応状況

**FACT:** 原因調査までで、コードや設定の修正はしていない。対象記事の未保存状態は残っている。

**PROPOSAL:** 修正を検討する場合は、候補セレクターを記事内へ限定する案と、同一の正規化済み著者リンクを重複排除する案を比較する。異なる著者へのリンクが混在する場合まで任意の先頭要素を採用すると、別メンバーへ保存するおそれがある。案の実装と検証は未実施である。

## 動作確認と次の検証

| 観測項目 | 結果 |
| --- | --- |
| 詳細HTTP応答 | 200 |
| タイトル・著者・日時・本文要素 | すべて存在 |
| 著者名と完全一致するリンク | 2個 |
| 両リンクの行き先 | 同一 |
| パーサー再実行 | 著者リンクの曖昧エラーを再現 |
| 修正後の成功確認 | 未実施。修正していないため |

次の回帰テストでは「同一著者・同一リンクの重複」と「異なる著者リンクの競合」を分ける必要がある。これはテスト案であり、追加済みテストとしては扱わない。
