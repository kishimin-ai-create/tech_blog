# HTTPS境界を維持してアーカイブの画像参照を回復する

## 結論

取得済み本文に残る古い画像参照を、確認済みのHTTPS URLへ完全一致で置換した。公開先を確認できないローカル添付参照は、個別の承認に基づき該当画像要素だけを除外した。本文全体の文字列置換や、すべてのHTTP画像を許可する変更にはしていない。

例には予約ドメインと架空の参照だけを使い、実URL、人物名、添付ファイル識別子は掲載しない。

## 発生した問題

### 症状・発生条件

JSON本文と元サイトのHTML詳細に、HTTP画像や `cid:` のローカル添付参照が含まれていた。既存の解析ではHTTPSと許可ホストを要求するため、記事の保存が失敗した。

### 影響

本文の取得に成功していても、画像参照の検証を通過できない記事が残った。

## 調査

実画像のHTTPS候補の到達状態を確認した。到達できる画像は置換候補とし、公開先が確認できない添付参照は別に扱った。別のHTTPSホストも、到達確認後に非公開の許可ホスト設定へ追加した。

## 原因

取得元本文の画像参照が、保存処理のURL契約に適合していなかった。すべてが同じ原因ではなく、HTTP参照、ローカル添付、未許可のHTTPSホストを区別した。

## 解決方法

次は実際の参照を含まない設定の説明例である。置換先ホストは事前に取得元またはCDNの許可設定へ登録されていることが前提となる。

```json
{
  "image_url_replacements": {
    "http://legacy.example/image.jpg": "https://cdn.example/image.jpg"
  },
  "omitted_image_urls": ["cid:/example-attachment.jpg"]
}
```

`app/services/archive_collection.py` の `_replace_image_urls` は `img[src]` を走査する。設定に完全一致する画像だけを置換または除外し、本文中の同じ文字列やリンクの `href` はこの処理では変更しない。両詳細形式でサニタイズと画像抽出の前に適用する。

| 検証境界 | 条件 |
| --- | --- |
| 置換元 | 絶対HTTP(S) URL、認証情報なし、標準ポート、長さ上限 |
| 置換先 | HTTPS、認証情報なし、標準ポート、許可ホスト、長さ上限 |
| 除外 | 完全一致のHTTP(S)または長さ・空白を検証した `cid:/` 参照 |
| 設定全体 | 各項目の件数上限、同じ参照への置換と除外の競合禁止 |

置換先ホストは対象行の準備と通信より前に検証する。個別の除外承認を、すべての添付参照を自動削除する許可とは扱わない。

## 動作確認

**FACT:** `tests/medium/test_archive_collection.py` でJSON・HTML両形式、完全一致、未指定、別参照、未許可ホスト、個別除外を検証した。保存本文と画像行を確認し、不適合な参照が残る場合は失敗することも固定した。実コマンドで回復後の記事を保存し、既存データの維持を確認した。

最終実装の全体検証は163テスト成功、総合カバレッジ89.88%、行91.25%、分岐84.13%。これは画像処理だけのカバレッジではない。

## 再発防止

回帰テストで置換範囲と許可ホスト境界を維持する。**PROPOSAL:** 置換候補は記事ごとに到達確認と承認根拠を非公開記録へ残す。除外した画像の内容は復元できたとは報告しない。
