# ブラウザーのセッション復元とログアウトの競合を扱う

管理画面では、短時間のアクセストークンをメモリに保持し、再読み込み時は HttpOnly Cookie を使ってセッションを復元する。復元の応答が遅れた場合、ログアウトの後に古い応答が届くと、画面上の認証状態を復活させてしまう可能性がある。

## 対応

profile-hub の [PR #118](https://github.com/kishimin-ai-create/profile-hub/pull/118) では、同一セッションインスタンス内の操作を直列化し、ログアウトや新しいログインで世代番号を進める。復元の完了時に世代が変わっていれば、その結果を採用しない。重複する復元要求は共有する。

JavaScript が保持するアクセストークンはメモリ内に置き、ログアウト開始時に消去する。サーバーへのログアウトが失敗した場合は、ローカルトークンが消えたこととサーバー側の失効が確認できたことを区別する。[PR #122](https://github.com/kishimin-ai-create/profile-hub/pull/122) の画面は、この失敗を表示する。

## 検証と限界

同一インスタンス内で復元応答を遅延させ、ログアウト後に古いトークンが復帰しないテストを実行した。PR #122 時点では管理画面のテスト 28 件が成功した。

この直列化は複数タブを横断しない。実ブラウザーの Cookie 動作や複数タブ間の競合は未検証であり、公開前に検証とセキュリティレビューが必要である。PR は積み重ねた開発ブランチ上の変更であり、main への統合や本番公開を意味しない。
