# アップロードのサイズ上限をread前の境界テストで確認する

## はじめに

画像ファイルの読み込み前に10 MiBの上限を設けた。この記事の問いは、サイズ超過を検出するだけでなく、超過ファイルを読んでいないことをどう確認するかである。

## 背景と目的

PRレビューでは、大きなアップロードを一度にメモリへ読み込むことが指摘された。今回の対応は受け入れるファイルサイズを制限するもので、画像の画素数まで制限する実装ではない。

## 実装

FACT: コミット `a99a19c` の `services/analysis/analyze.py` は、読み込みより前に次の条件を評価する。

```python
if image_file.size > 10 * 1024 * 1024:
    raise HTTPException(status_code=402, detail="file size limit")

uploaded_image_bytes = await image_file.read()
```

10 MiBは10,485,760バイトであり、ちょうど上限のファイルは条件に該当しない。HTTP 402はこの実装が採用している値であり、本記事は一般的な推奨ステータスとして説明していない。

## 検証

| 入力サイズ | テストで確認した結果 |
| --- | --- |
| 0 | モックの生成処理を通る |
| 10 MiB | モックの生成処理を通る |
| 10 MiB + 1バイト | HTTP 402、readを呼ばない |

超過ファイルの偽物では、readが呼ばれるとAssertionErrorを発生させる。したがって、例外ステータスの確認だけでなく、読み込みを回避したことも確認できる。0バイトのケースは画像デコーダをモック化しているため、実際の空ファイルが有効な画像になるという意味ではない。

セッションの最終記録は15テスト成功、カバレッジ96.71%。執筆時には境界テストのコードを確認したが、再実行していない。

## 結果と制約

FACT: ハンドラ内のreadより前に超過を拒否する。INFERENCE: この条件はハンドラが読み込む入力の大きさを制限する。ただし、multipart受信段階の資源使用、展開後の画素数、画像サイズ不明の場合、段階的なデコードはこのテストで保証していない。

## 次回どうするか

PROPOSAL: ファイルのバイト数、デコード後の画素数、受信時の制限を別の契約として検討する。今回の対応を画像処理全体のメモリ問題の解消と報告しない。
