# Pillowで絵文字が四角になる原因を、書記素とフォントに分けて調べる

## 結論

文字列を絵文字単位で分割できても、その形をフォントが持っていなければ描画できない。glyph-forgeでは、英数字・日本語に使っていたIPAex Gothicを維持し、絵文字の書記素に同梱のNoto Emojiを選ぶことで、😀と🚀が同じ欠落グリフになる問題を修正した。

対象は、Pillowで文字を繰り返し描く画像生成処理を実装する人である。2026年10月22日、WindowsのPython 3.12.4、Pillow 10.3.0、regex 2023.10.3で調査した。結合絵文字の文字組みに必要な実行環境は[別の記事](./150-pillow-raqm-fribidi-runtime.md)で扱う。

## 発生した問題

### 症状

利用者が提示したPNGでは、文字の輪郭を構成する各セルが、四角に交差線の入った記号になっていた。元の入力値は確認できなかったため、ローカルで😀と🚀を使って最小再現した。

```python
from glyph_forge.services.text_image_renderer import render_text_grid_image

first = render_text_grid_image([["😀"]], 40)
second = render_text_grid_image([["🚀"]], 40)
print((first.size, first.tobytes()) == (second.size, second.tobytes()))
```

リポジトリの依存関係とパッケージをインストールした環境で実行した結果、修正前は`True`だった。異なる絵文字を渡しても出力が一致していた。

### 発生条件と影響

`load_font()`が常に`ipaexg.ttf`を返し、セルの計測にも描画にも同じフォントを使っていた。文字列は受け付けられ、PNGも生成されるが、選んだ絵文字を識別できなかった。

## 調査

### 書記素が一つのセルへ渡ることを確かめる

書記素は、利用者が一文字として認識する単位を指す。`👩‍🚀`のように複数のコードポイントからなる絵文字もある。

既存テストには、描画関数を差し替えて、`👩‍🚀`が一つのセルへ渡ることを確かめるものがあった。このテストが保証するのはグリッドへ渡す値であり、実際のフォントが宇宙飛行士を描けることではない。

### 従来フォントのマスクを比べる

`font.getmask()`で、😀、🚀、比較用のU+10FFFFのマスクを調べた。従来フォントでは、前二者がそれぞれ比較用文字と同じマスクになった。セルへの分割と、選択したフォントによる描画を別々に調べる必要があった。

## 原因

従来フォントで今回の絵文字を描くと欠落グリフになり、別フォントへ切り替える処理もなかった。

これはローカル再現で確認した原因である。元の報告画像については、使用した絵文字やデプロイ版が未確認なので、同じ生成条件まで再現したとは扱わない。

## 解決方法

絵文字の判定には既存依存のregexを使った。次は採用した判定式である。

```python
_EMOJI_PATTERN = regex.compile(
    r"\p{Extended_Pictographic}|\p{Regional_Indicator}|\u20e3"
)
```

絵文字、国旗の地域指示記号、キーキャップを対象に、書記素ごとにフォントを選ぶ。セルサイズも選択後のフォントで計測し、サイズだけ従来フォントで決める不整合を避けた。混在する枠文字は、同じフォントの連続部分へまとめ、共通のベースラインで描画する。

従来の`load_font(20)`は、文字を指定しなければ引き続きIPAex Gothicを返す。従来フォント自体に絵文字を追加した修正ではないため、直接のフォントマスク比較と、画像生成結果の比較は区別する。

採用したNoto Emojiは単色版である。文字を敷き詰める用途に合わせ、既存の内側・外側の色設定を絵文字にも適用する。フォントとOFLライセンスをパッケージへ含め、Windowsに偶然インストールされているフォントに依存しない構成にした。

## 動作確認

追加テストでは、異なる絵文字が異なる画像になること、指定した色と透明度が使われること、セル端で欠けないことを確認した。最初の最小再現は修正後に`False`となった。

```powershell
python -m pytest -q tests/test_glyph_forge/test_emoji_rendering_medium.py
python -m build
```

最終的な新規描画テストは、Linuxの本番用イメージ内で39件すべて成功した。wheel内のフォントとライセンスがリポジトリのバイト列と一致することも確認した。英数字・日本語は従来フォントのマスクと比較し、既存描画を維持した。

## 再発防止

文字列の分割だけをモックで確かめるテストに加え、同梱フォントで描いた出力を検証するテストを残した。フォントの対応範囲を超えるUnicode文字は今後も未対応になり得る。すべての絵文字への対応や、フルカラー表示を保証したものではない。

## まとめ

絵文字の入力検証、書記素の分割、フォントの選択、描画結果には別々の確認が必要だった。今回の欠落グリフは、実際のフォントで出力を比べることで再現し、文字ごとのフォント選択で修正できた。
