# Argon2idのパスワード処理をログイン機能と区別する

管理者認証に向けて、profile-hubではパスワードのハッシュ化と検証を小さなユーティリティとして追加した。[PR #77](https://github.com/kishimin-ai-create/profile-hub/pull/77) の実装はBunの非同期 `Bun.password.hash` を使い、Argon2idのメモリを65536 KiB、反復回数を2に指定する。

テストでは同じパスワードから異なるハッシュが作られること、正しいパスワードと誤ったパスワードの判定、長いUnicode入力を確認した。不正なハッシュで起きる例外は握りつぶさず呼び出し側へ伝える。

このPRはログイン画面、管理者の初期登録、試行回数制限、セッション発行を提供しない。ハッシュ関数があるだけで認証全体が完成するわけではなく、呼び出し側でエラー処理とアクセス制御を組み合わせる必要がある。メモリ量は同時リクエスト数にも関係するため、運用時の負荷確認も残る。

使用したAPIの仕様は[Bunのパスワードハッシュドキュメント](https://bun.com/docs/runtime/hashing)を参照した。
