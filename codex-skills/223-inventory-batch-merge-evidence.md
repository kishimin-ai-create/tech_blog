# AIによる分割分類を統合するときに根拠を失わない

## 結論

大量の履歴をAIに分類させるとき、入力を分割しても、最後の統合で同じ根拠を複数のグループへ割り当てる応答が生じる。分割ごとにIDを検証し、統合先が競合する提案は採用せずに元のグループを残すことで、曖昧な割り当てによる二重計上を避けられる。

## 発生した問題

Windowsで稼働するPython製のプロンプト定期分析は、直近7日間の履歴をモデルで分類する。2026年11月6日の定期実行は `ANALYSIS_FAILED:ValueError` となった。通知は例外の型だけを記録するため、その実行の厳密な失敗箇所は分からない。

同じ時点の対象283件で再実行すると、30件単位の分類でも不正な結果があり、10件単位にしても一部のバッチは修復後に失敗した。さらに、分類後の統合応答の一例では、140グループに対し85回のID指定があり、異なるIDは75件だった。つまり10回分が重複していた。

## 対応

1. 履歴を最大10件のバッチに分け、各入力IDが一度ずつ分類または除外されたことを検証する。
2. 不正なバッチは一度修復し、なお不正なら二分してそれぞれ再検証する。単一件でも不正なら失敗する。
3. 分類済みグループをモデルに見せ、意味の近いグループの統合案を得る。
4. 同じグループIDが複数の統合案で使われた場合、競合する案を採用せず元のグループを保持する。未指定のグループも残す。

統合を見送ると関連する依頼を別々に数え、候補の頻度を過小評価する可能性がある。モデルによる意味判断を完全に保証するものではない。

## 動作確認

`python -m unittest discover -s tests` は68件成功した。対象期間の実データを使った通知なし実行では、分類、統合、既存スキル照合が12分49秒で完了し、最終候補は2件だった。通知と本番KVSの結果はこの検証には含まれない。

## 学びと制約

JSONが構文上正しくても、IDの一意性や参照先の存在は別に検証する必要がある。分割で出力の負荷を抑える一方、グループをまたぐ統合の品質と計算時間は新たな課題になる。関連する前回の調査は [分類結果のID検証](222-inventory-classification-evidence-validation.md) に記録した。
