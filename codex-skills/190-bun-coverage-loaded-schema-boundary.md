# カバレッジ100%でも読み込まれていないファイルがあった

テストカバレッジの数値は、集計対象になったコードについての情報である。[PR #63](https://github.com/kishimin-ai-create/profile-hub/pull/63) の時点ではBunが関数・行とも100%と表示したが、その対象は設定ファイルで、スキーマ全体が読み込まれた結果ではなかった。

後に公開APIがスキーマを読み込むようになると、[PR #67](https://github.com/kishimin-ai-create/profile-hub/pull/67) では25テストが成功していても関数カバレッジは57.14%になった。数値が下がったこと自体が障害というより、以前は集計に含まれていなかった範囲が見えるようになったことを示している。

そこでスキーマのインデックスをPostgreSQLの `pg_indexes` と照合するテストや接続設定のテストを追加し、DBを有効にしたCIで測定した。当時の27テストの結果は関数100%、行98.33%だった。その後の [PR #79](https://github.com/kishimin-ai-create/profile-hub/pull/79) では51テスト、関数98.93%、行99.24%を確認した。

これらはそれぞれ別時点・別対象の結果であり、数値だけで品質や未実行コードの不存在は証明できない。どのファイルが集計され、DBテストが実際に走ったかを合わせて見る。
