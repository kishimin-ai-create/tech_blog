# Python収集処理で一覧ページの循環リンクに負けず履歴を巡回する

一覧ページの「次へ」リンクだけを信頼すると、リンクが先頭ページへ戻るサイトで過去データを取りこぼすことがあります。本記事では、設定されたページ番号を順に試し、詳細ページから見つかった作成者別の一覧もバックフィル対象に加える実装を、匿名化したテストで検証した記録をまとめます。

## 結論

- 番号付き一覧は`page=0`から順に取得し、空ページまたは契約エラーで終了する。
- 詳細ページから得た作成者パスを保持し、バックフィル時だけそのパスも巡回する。
- 同一ページ内容の繰り返しを検知し、循環や無限巡回を防ぐ。
- Python 3.14、39テスト、分岐込みカバレッジ82.62%で確認した。

## 循環リンクだけでは履歴を保証できない

従来の実装は、一覧ページの`next`リンクをたどる方式でした。しかし、`next`が先頭ページを指すと、既訪問ページの検出で止まります。この検出は無限ループ防止には有効ですが、番号付きURLでしか到達できない過去ページを見つけられません。

そこで、一覧パスに`{page}`が含まれる場合は、`config.list_path.format(page=n)`を使ってページ番号を増やします。ページ番号を使わない設定では従来どおり`next_path`を利用します。

```python
if numbered_pages:
    page_number += 1
    page_path = config.list_path.format(page=page_number)
else:
    page_path = page.next_path
```

## 詳細ページから作成者別の履歴を発見する

一覧ページに掲載される範囲だけでは、作成者ごとの過去履歴を網羅できない場合があります。詳細ページの作成者リンクからパスを抽出し、バックフィル時にそのパスを起点として巡回します。

作成者別巡回では、次の安全策を入れています。

1. 既に取得した作成者パスを集合で重複排除する。
2. ページリンクがあればそれを優先し、番号付き設定ではページ番号を補完する。
3. 同じレコード列を返すページを検出して停止する。
4. `COLLECTOR_MAX_PAGES`を超えた場合は未完了として扱う。

## テストで固定した振る舞い

`tests/medium/test_collection_sequence.py`では、匿名化したHTTP応答を使い、次を確認しています。

- 循環する`next`リンクがあっても番号付きページ2まで取得する。
- 詳細ページで見つかった作成者別パスから、新しい履歴レコードを取得する。
- 空ページで正常終了し、失敗件数を増やさない。
