# 入力変更後に古い画像生成結果をプレビューしない

## はじめに

画像生成のリクエストを送った後、応答が戻る前に入力を変更できる画面では、変更前の画像が後から表示されることがある。Mojicaの画像プレビュー実装で、この古い応答を画面に反映しない方法を試した。

## 前提・環境

- 対象: MojicaのReact・TypeScriptフロントエンド
- 実行日: 2026年11月17日
- 検証: Vitest、Testing Library、MSWを使ったブラウザテスト
- 作業状態: [Issue #50](https://github.com/kishimin/mojica/issues/50)の画面変更はローカルで実装中で、マージ・本番反映は未完了

## やってみた結果

入力の変更を表す番号を持ち、リクエスト開始時の番号と応答時の番号が同じ場合だけプレビューを更新するようにした。ローカルのテストでは、応答を待っている間に文字を変更すると、古い画像が表示されず、画像用のObject URLも作成されないことを確認した。

## 実装・検証

### 入力変更を識別する

入力が変わったら番号を進め、表示中のプレビューを消す。送信時にはその番号を控える。

```ts
const submittedRevision = revision.current;

// 入力変更時
revision.current += 1;
setPreview(undefined);
```

画面上の文字や色の変更に加え、画像タイプの選択変更でも番号を更新する。プレビュー用に作ったObject URLは、プレビューの更新時または画面の破棄時に解放する。

### 応答を反映する前に照合する

```ts
if (submittedRevision !== revision.current) return;
setPreview({ response, url: URL.createObjectURL(response.data) });
```

この比較は古い応答を表示しないためのものであり、送信済みの通信やサーバー側の画像生成そのものを中止するわけではない。エラー応答も解析後に番号を照合し、変更前の入力に対するエラーを現在の画面に表示しないようにした。

### 応答を遅延させて確認する

MSWの応答をPromiseで保留し、リクエスト開始後に入力を変更してから応答を返すテストを追加した。次のコマンドで対象テストが成功した。

```powershell
npx vitest run --project=unit src/features/image-generation/components/ImageGenerationForm/ImageGenerationForm.small.test.tsx -t "discards a response"
```

対象テスト1件が成功した。画面全体の回帰や本番環境の動作を、この1件だけで保証するものではない。

## つまずいたところ

送信時点の入力と画面の現在の入力が異なる状態でも、非同期の応答は到着する。表示の更新を応答の到着だけに結び付けると、現在の入力と画像の対応を画面上で判断できない。番号を照合することで、応答が現在の入力に対応している場合だけ表示する。

## 学んだこと

非同期の結果を画面に出す前に、その結果が現在の入力に対応しているか確認すると、待機中の編集による表示の食い違いを防げる。通信自体の中止や画像生成の資源節約が必要な場合は、別途キャンセルの仕組みを検討する必要がある。

## まとめ

入力変更時のプレビュー破棄と、応答時の番号照合を組み合わせ、古い画像を表示しない挙動をテストで確認した。画面変更全体の検証と公開は今後の作業である。
