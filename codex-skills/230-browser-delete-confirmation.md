# 削除確認の取消と承認をブラウザーで検証する

## 結論

作品を永久削除する前の確認について、取消では削除要求を送らず、承認したときに DELETE を送り一覧から消すことをブラウザーで確認した。[PR #288](https://github.com/kishimin-ai-create/profile-hub/pull/288) はドラフトで、アプリの main には未マージである。

## 背景

作品管理の Issue #14 は永久削除の明示的な確認を要求している。確認ダイアログを表示するだけでは、取消と承認がそれぞれ正しい操作につながるか分からない。

## 検証

テスト用の作品一覧を用意し、削除ボタンを2回操作した。最初はダイアログの対象名を確認して取消し、削除要求がなく項目が残ることを確認した。次は同じ確認を承認し、DELETE が1件送られ、空状態になることを確認した。

Chromium と WebKit でそれぞれ成功した。ブラウザー側で API 応答を代替しているため、実 DB からの削除はこのケースでは検証していない。[Nightly](https://github.com/kishimin-ai-create/profile-hub/actions/runs/42353676685) は5ジョブ成功した。

## 学び

確認ダイアログのテストでは、表示だけでなく取消時の副作用なしと、承認後の要求・表示の変化を区別して確認できる。
