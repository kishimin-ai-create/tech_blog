# API の接続先をホスト名とパスに分けてテストする

## 背景

公開ホームでプロフィール API を呼び出すとき、通信共通処理の既定値は `/api` だった。一方、環境変数の設定例は `http://localhost:3001` のようなホスト名である。この二つを同じベース URL として扱い、リクエストに `/public/profile` を渡すと、環境変数を設定した場合に `/api` が欠ける。

## 再現と対応

MSW で `https://api.example.test/api/public/profile` を受け付けるテストを追加し、環境変数に `https://api.example.test` を設定した。変更前の実装は期待した URL に到達せず、テストが失敗した。

ホームのリクエストでは、API のオリジンをベース URL とし、パスを `/api/public/profile` として明示するようにした。環境変数を省いたときも同じパスを相対 URL として使う。レスポンスのプロフィールが null の場合と、不正な形の場合は区別して扱う。

## 検証と限界

修正後、公開画面の Vitest は 29 件成功し、型チェック、Lint、HTML 検査、整形確認、ビルドも成功した。Vitest の既定 fork プールはローカルで停止したため、threads プールを使用した。テストは MSW による HTTP 応答を使用しており、実 API とブラウザーをつないだ確認ではない。

## 学び

環境変数がオリジンなのか `/api` を含むベースパスなのかを先に決め、その値を設定したテストで実際のリクエスト先を検証する。既定値だけで成功するテストでは、環境別のパス欠落を見逃す場合がある。
