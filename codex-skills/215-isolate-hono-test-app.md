# Honoのテストでルート追加が失敗した原因と解決方法

## 結論

複数のテストが同じHonoアプリを共有し、先にリクエストを処理した後で別のテストがルートを追加していた。テスト用ルートを追加する側に新しいアプリを生成することで、共有ルーターの構築順序から分離した。

## 発生した問題

### 症状

```text
Can not add a route since the matcher is already built.
```

### 発生条件

- BunでAPIのSmallテストを実行するCI。
- OpenAPIのテストが共有アプリの `/docs/json` にリクエストする。
- 同じプロセス内の別テストが、その共有アプリへテスト用ルートを追加する。

### 影響

管理画面の変更を含むPRで、API Smallが失敗してCI全体が失敗した。

## 調査

### 共有アプリの構築順序を確認する

失敗ログではOpenAPIテストの後にルート追加側が実行されていた。共有アプリに `/docs/json` をリクエストしてからルートを追加する操作を同一プロセスで再現すると、同じエラーが発生した。

## 原因

先のリクエストで共有アプリのSmartRouterのmatcherが構築され、その後のルート追加が拒否された。個別のテストが成功しても、同じインスタンスを使うテスト間の順序によって失敗し得る。

## 解決方法

テスト用ルートを追加するファイルでは、共有のdefaultアプリではなく、既存の `createConfiguredApp()` から生成したインスタンスを使用した。プロダクトのアプリ配線は変更していない。

## 動作確認

- ローカルのAPI Small: 101件成功。
- 新しいインスタンスには、共有アプリのリクエスト後でもテスト用ルートを追加できることを確認。
- [後続ブランチのNightly](https://github.com/kishimin-ai-create/profile-hub/actions/runs/41714266326) では、PostgreSQLを用いるAPIジョブが成功。Nightly全体は記事作成時点で実行中。
- ローカルの全体カバレッジはPostgreSQLが利用できず、DB依存33件がスキップされ、閾値を満たさなかった。

## 再発防止

ルートを変更するテストは、それぞれ独立したアプリを生成して所有する。テストの実行順を固定して共有状態を隠す方法は採っていない。

## まとめ

- 症状: matcher構築後のルート追加が失敗した。
- 原因: リクエストとルート追加が異なるテストから同じアプリに対して行われた。
- 修正: テストごとに設定済みアプリを生成し、変更対象を分離した。
- 教訓: テスト間で状態を持つアプリを共有するときは、単体の成功に加えて同一プロセスでの実行順序も確認する。
