# file画像だけを除外して記事本文を保存する

## 結論

記事本文に端末内ファイルを指す `file:` の画像があると、画像URLの検証で記事全体が保存できない場合がある。今回の対応では、取得できない画像だけを画像一覧と本文HTMLの両方から除外した。本文と取得可能な画像は保持し、HTTPSと許可ホストの検証は維持した。

PythonでHTMLを収集し、本文と画像を別々に保存する処理の保守担当者を対象とする。確認日は2026年10月15日、環境はWindows、Python 3.14.7である。

## 発生した問題

### 症状

公式ページの取得はHTTP 200だったが、詳細解析で次の例外が発生した。

```text
ParseContractError: URL leaves the approved host boundary
```

### 発生条件と影響

本文の画像要素に `file:` URLが含まれていた。タイトル、著者、日時、本文の要素は存在していたが、画像抽出中に例外となり、その記事はDBへ保存されなかった。実際の端末パスや添付識別子は掲載しない。

## 調査

最初は別の記事と同じ `ParseContractError` に見えたため、同一原因かを確認した。取得ログの記事IDと保存済みIDを比較し、未保存の詳細だけを再取得した。取得成功を確認してから同じパーサーへ入力し、例外メッセージと発生箇所を調べた。

その結果、今回の例外は `_assets` から `_asset_path`、`_relative_path` と進む画像URL検証で発生していた。別記事の著者リンク照合エラーとは原因が異なった。

## 原因

画像URLの検証は、解決後のスキームがHTTPSで、ホストが取得元または許可済みCDNに属することを要求する。`file:` はこの契約を満たさない。CDNホストを追加しても、端末内ファイルを取得できるURLにはならない。

## 解決方法

取得できない画像を除外する方針が選択されたため、共有HTMLパーサーの既存の `blob:` 除外へ `file:` を追加した。次は画像抽出側の実装抜粋である。

```python
if urlsplit(source).scheme in {"blob", "file"}:
    # Browser- and device-local images are unavailable to the collector.
    continue
```

画像のメタデータだけを除外すると、本文HTMLに壊れた画像参照が残る。サニタイズ側でも同じスキームを検出し、該当する `img` 要素を削除した。本文全体や他の画像は削除しない。除外後の画像位置は、残った画像の件数から採番する。

この対応は、[アーカイブの画像参照を完全一致で回復する対応](./108-explicit-archive-image-recovery.md)とは適用箇所が異なる。今回は共有HTMLパーサーのスキーム単位の処理であり、私設アーカイブの置換設定は変更していない。

## 動作確認

`tests/small/test_source_adapter.py` に、通常の画像の間へローカル画像を挟む回帰テストを追加した。修正前はローカル画像の3ケースが失敗し、修正後はパーサーテスト18件が成功した。

| 観測した項目 | 結果 |
| --- | --- |
| `file:`、`FILE:`、ホスト付きのfile URL | 画像を除外し、本文を保持 |
| 除外画像の前後にあるHTTPS画像 | 両方を保持し、位置は0・1 |
| 未許可HTTPS、HTTP、data、JavaScriptの画像URL | 引き続き拒否 |
| 全体テスト | 188件成功 |
| 全体の分岐を含むカバレッジ | 89.88% |
| 実記事の再取得 | 保存1件・既存108件スキップ・失敗0件 |
| 保存後のDB | 対象記事は1行、本文と画像5行を保持、file参照なし |

整形、Ruff、strict mypyも成功した。検証コマンドはリポジトリルートから `uv run ruff format --check .`、`uv run ruff check .`、`uv run mypy app tests`、`uv run pytest acceptance tests --cov=app --cov-report=term-missing -q` を実行した。uvはリポジトリ指定の0.12.24を一時的なツール環境から使用した。

## 再発防止と制約

回帰テストで、本文を保存できることと、不正な画像URLを引き続き拒否することの両方を固定した。画像の除外を、ホスト境界の緩和へ広げない。

元のローカル画像は復元できていない。画像の完全な保存が必要な用途では、この除外方針をそのまま採用せず、欠落を許容できるかを先に決める必要がある。変更を戻す場合は、対象コミットを通常のレビュー経由で取り消すが、既に省略して保存した画像はそれだけでは戻らない。
