# 公開画面から実際の Hono ルートを呼ぶブラウザーテスト

## 背景

公開画面のブラウザーテストでは、Playwright が API リクエストを捕まえて固定レスポンスを返していた。画面内の表示と遷移は検証できる一方、画面が実際の Hono ルートへアクセスできるか、オリジン間の CORS 設定が合うかは確かめていなかった。

## 対応

テスト専用の Hono アプリを別ポートで起動し、公開画面を別のポートで立ち上げた。API の公開ルートと CORS は実装を使用し、プロフィール、お気に入り、作品の取得にはメモリー上のデータを返す関数を注入する。ブラウザー側で API を差し替えず、ホームから Hobby の一覧と連絡先まで操作する。

通常のブラウザーテストとは別の Playwright 設定にし、テスト用サーバーの起動と終了を管理する。夜間 CI でもこの設定を実行する変更を追加した。

## 検証と限界

ローカルの Chromium と WebKit で各1件成功した。公開画面の52テストと API の Small 101テストも成功した。データアクセスはメモリー実装のため、PostgreSQL の接続や保存結果はこのブラウザーテストでは保証されない。PostgreSQL を用いる API テストと組み合わせても、本番設定そのものを検証したことにはならない。

## 学び

画面テストでネットワーク応答を差し替える場合、表示やエラー処理を手早く検証できる。別途、ブラウザーから実際の API ルートまでつなぐテストを置くと、パス、オリジン、CORS の配線を確認できる。どこから先をテスト用実装に置き換えたかを結果に書き、DB や本番環境の保証と混同しない。

根拠: [実 Hono ルートを使う公開ブラウザーテスト #207](https://github.com/kishimin-ai-create/profile-hub/pull/207)。PR はドラフトで、夜間 CI の結果は実行ごとに確認が必要。

## 追加検証：専用 PostgreSQL を通す

後続の [#208](https://github.com/kishimin-ai-create/profile-hub/pull/208) では、夜間 CI に専用の空 PostgreSQL を用意し、マイグレーション後、設定済み Hono API とブラウザーを接続した。DB 必須モードで [夜間 CI](https://github.com/kishimin-ai-create/profile-hub/actions/runs/41359081745) の Chromium と WebKit が成功した。

この追加検証は CI のテスト用 DB と設定での結果であり、本番環境を検証したものではない。ローカルでは PostgreSQL が利用できず、DB モードは実行していない。接続先診断の追加修正を含む後続コミットも、[夜間 CI](https://github.com/kishimin-ai-create/profile-hub/actions/runs/41359321957) の全5ジョブが成功した。
