# AIによる分類結果でIDの欠落・重複を検出する

## 結論

多数のログをAIに分類させる場合、JSONの形式が正しくても、入力IDの欠落や重複を検証する必要がある。今回の定期分析では、不正な結果に対して一度だけ補正を試みる処理を追加したが、実データでの再実行は補正後も失敗した。問題は未解決である。

## 発生した問題

プロンプトの定期分析が次の状態を通知した。

```text
分析: FAILED / KVS: SAVED
失敗理由: ANALYSIS_FAILED:ValueError
```

分析は失敗したが、失敗結果のKVS保存は成功していた。通知には例外の種類しか含まれず、元の実行がどの検証で失敗したかは特定できない。

## 調査

対象はPython製のローカル定期分析で、直近7日間のログをCodexへ渡し、AIが返す分類を検証する。プロンプト本文は出力せず、失敗時刻における件数と文字数だけを確認した。

前処理後は248件、入力は138,360文字で、設定上限の250,000文字以内だった。ログ読み取りも成功した。

同じ期間のデータで通知を送らずに分析を再実行したところ、返却IDは221件、そのうち異なるIDは210件だった。入力IDのうち38件が欠落し、11件が重複していた。入力ID以外のIDはなかった。

## 原因

この再現実行では、全入力IDを一度ずつ分類する契約に応答が違反し、`validate_analysis`が`ValueError`を送出した。形式がJSONでも、配列内の要素が入力を網羅することまでは保証されない。

当初の通知では詳細が保存されていないため、同じ原因だったかは不明である。

## 対応

不正な分類が返った場合、元の入力と前回の応答を未信頼データとして再提示し、分類の補正を一度だけ依頼する処理を追加した。再生成後も同じ検証を通し、通らなければ失敗として扱う。入力上限を超える場合は途中で切り詰めない。

この対応は失敗結果を正常扱いにしないための限定的な試みであり、実データでの成功を保証するものではない。

## 動作確認

| 確認 | 結果 |
| --- | --- |
| 回帰テストを含むテスト全体 | 60件成功 |
| ブランチカバレッジを含む全体カバレッジ | 95% |
| mypy strict・Pythonコンパイル | 成功 |
| 通知なしの実データ再実行 | 補正後も分類検証に失敗 |

## 再発防止と残る課題

追加したテストは、欠落・重複した応答を再検証する経路を確認する。一方、実データでは補正が成功しなかったため、定期分析は未復旧である。

次の検討案は、入力を分割して個別に分類し、異なる分割間の同じ意図を統合することだ。統合後にも全IDの一意性と網羅性を検証する必要がある。分割すれば必ず成功するという検証結果はまだない。
