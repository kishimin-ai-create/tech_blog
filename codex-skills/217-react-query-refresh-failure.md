# React Queryの更新失敗で表示中の内容が消えた原因と解決方法

## 結論

共通表示がクエリのエラー状態を一律に扱っていたため、取得済みデータがある更新失敗でも内容を隠していた。更新失敗では以前の内容を残し、古い可能性と再試行を表示した。

## 発生した問題

### 症状

初回に表示した公開データが、バックグラウンド更新に失敗すると画面から消えた。

### 発生条件

- ReactとTanStack Queryを利用する公開画面。
- 初回取得が成功し、その後の再取得が失敗する。
- 共通コンポーネントはクエリのerror状態でエラー表示だけを描画していた。

### 影響

一時的な通信障害でも、訪問者が先ほどまで見えていた内容を読めなくなった。

## 調査

実際のQueryClientを使い、取得成功、再取得失敗、再試行成功を順番に発生させるテストを追加した。失敗後に内容を探すアサーションは、修正前に失敗した。

## 原因

初回失敗と取得済みデータを持つ更新失敗は、どちらもerror状態になり得る。従来の表示はその違いを見ず、子要素を描画しなかった。

## 解決方法

更新失敗を `isRefetchError` で識別し、その場合は取得済み内容を表示し続ける。併せて内容が古い可能性を伝え、再試行ボタンを表示する。初回取得失敗の表示は維持した。

## 動作確認

- 公開画面の全66テストが成功。
- 型検査、Lint、markup lint、リポジトリの整形チェックが成功。
- カバレッジはstatements 90.86%、branches 92.36%、functions 98.33%、lines 92.70%。
- [Nightly CI](https://github.com/kishimin-ai-create/profile-hub/actions/runs/42004671079)は記事作成時点で実行中。

## 再発防止

コンポーネントの状態を手作業で模倣するだけでなく、QueryClientを通じて成功から失敗、再試行までの遷移をテストに残した。

## まとめ

更新失敗時には、最後に得られた内容を表示し続けることと、古い可能性を利用者へ明示することを両立した。[PR #246](https://github.com/kishimin-ai-create/profile-hub/pull/246)はドラフトで、マージされていない。
