# PostgreSQL BIGINT の ID を API の入力境界で検証する

PostgreSQL の `BIGINT` を文字列で API に公開する場合、JavaScript の `Number` を介すると大きな ID の精度が失われる。profile-hub は ID を文字列のまま返し、管理 API の詳細取得では形式と PostgreSQL の符号付き BIGINT の上限を照合してから保存層へ渡す。

## 検証の位置

[PR #129](https://github.com/kishimin-ai-create/profile-hub/pull/129) では、正の10進数だけを許し、先頭のゼロや範囲外の値を拒否する。桁数を先に制限してから `BigInt` に変換し、上限 `9223372036854775807` と比較する。存在しない有効な ID は、不正な ID と区別して 404 を返す。

認証されていない要求は保存層に到達しない。DB 検索では一致する行だけを取得し、ID を文字列に直して返す。

## 検証と範囲

Small テストは未認証、ゼロ、先頭ゼロ、上限超過、非数字、存在する ID と存在しない ID を確認した。実 PostgreSQL から作成済み項目を取得する Medium テストも CI で成功した。

この結果は詳細取得の境界についてのもので、プロジェクト全体の完成や本番公開を意味しない。後続の更新・削除も同じ範囲検証を使うが、入力の共通化や他の ID 境界の確認は別途必要である。
