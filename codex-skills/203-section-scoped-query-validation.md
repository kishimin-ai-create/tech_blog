# セクション別一覧の取得条件とキャッシュを揃える

## 背景

公開サイトの作品には Engineering と Hobby がある。API は `section` を指定して作品を返すが、画面で同じクエリキーを使うと、キャッシュ上で両方の結果を区別できない。異なるセクションのデータを表示しないことも画面の要件だった。

## 対応

作品一覧の取得関数にセクションを渡し、API のクエリパラメーターと TanStack Query のキーの両方に含めた。レスポンスの各作品が要求したセクションに属することも検査し、異なるセクションが返った場合は一覧を表示せずエラーにする。作品のリポジトリとデモは null を受け入れ、存在する URL は HTTP(S) に限定した。

## 検証と限界

Engineering の取得条件と Hobby の混入拒否をテストし、既存の Hobby テストも実行した。公開画面は全49テスト、型チェック、Lint、HTML 検査、整形確認、ビルドが成功した。固定 API 応答を使う Hobby のブラウザー操作は Chromium と WebKit で成功した。

これらは実 API とブラウザーをつないだ検証ではない。画像の表示や実機のモバイル確認も未完了である。

## 学び

結果が入力条件によって変わる取得処理では、取得条件とキャッシュキーを対応させる。レスポンスのセクション検査は、API のフィルタリングを代替するものではなく、画面側がデータを表示する前に契約違反を検出するための追加の境界である。
