# Gitの著者情報を直すとき、設定と履歴とリモートを分けて確認する

## はじめに

Gitのユーザー名を変更しても、過去のコミットに記録された著者情報は変わりません。今回の作業では、今後の設定変更、過去の履歴修正、GitHubへの反映を別々に検証しました。履歴修正を検討する人向けの、実施記録です。

## 前提・環境

2026年10月21日、Windows / PowerShell、blog-wordcloudでの作業です。履歴修正にはgit-filter-repoを使用しました。以下の照会コマンドは読み取り専用です。

## やってみた結果

ローカル14ブランチの98コミットを処理し、86コミットの対象識別情報を更新しました。親コミットが変わる影響もあり、処理対象98コミットすべてのハッシュが変わりました。処理により署名12件も除去されました。ファイル内容を表すtreeは比較して維持を確認しました。

リモート更新は別途、対象2ブランチと履歴置換について明示確認を受けて実施しました。その一回の承認を、以後の履歴変更へ流用していません。

## 実装・検証

### 今後の設定と過去の記録を調べる

実行場所は対象リポジトリです。メールアドレスを表示するため、出力を公開ログへ転載する際は伏せます。

```powershell
git config --show-origin --get user.name
git config --show-origin --get user.email
git log -5 --format="%h %an <%ae> / %cn <%ce>"
```

設定の取得結果と、コミット内のauthor・committerは別の情報です。GitHubの認証アカウントとも分けて扱いました。

### バックアップと比較基準を先に用意する

実施前にbundleと参照のスナップショットを保存しました。今回のmainは旧 `8232b904` から `6f2e63fc` へ変わりましたが、両者のtreeが同一であることを確認しました。

照会例は次のとおりです。プレースホルダーは実際のコミットへ置き換えます。

```powershell
git rev-parse "<before>^{tree}"
git rev-parse "<after>^{tree}"
git diff <before> <after> --
```

treeの一致はファイル内容の比較です。著者、日時、メッセージ、署名の扱いまで同一である証明にはなりません。それらは別の比較項目にしました。

## つまずいたところ

ローカル履歴を置き換えた段階では、リモートに旧履歴が残りました。その状態で通常のpull/pushが成立するとは扱わず、ローカル修正とリモート更新を分けて説明しました。

共有履歴の置換は共同作業者へ影響します。この記事はforce pushの実行手順を提供するものではありません。今回の結果を、新たな履歴置換の許可や一般的な推奨とは扱わないでください。

## 学んだこと

「ユーザーを揃える」という依頼でも、設定、履歴内の識別情報、GitHub認証、リモート参照には別の確認が必要でした。ファイル差分が空でもコミットハッシュや署名が変わるため、内容だけを見て影響なしとは判断できません。

## 根拠と制約

根拠は今回のidentityバックアップ、filter-repoの対応表、修正前後のtree・識別情報比較、対象2ブランチのリモートSHA照合です。個人メール、バックアップ実体、認証情報は掲載していません。履歴置換後の共同作業者全員のローカル復旧までは確認していません。
