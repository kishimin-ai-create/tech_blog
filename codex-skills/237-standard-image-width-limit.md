# 文字アートの標準画像が幅の上限を超えた原因

## 結論

`mojica`を`Web`で描く標準画像は、Glyph ForgeのローカルDockerイメージで途中の出力幅が2310ピクセルとなり、幅2048ピクセルの制限で拒否された。公開サイトでも同じ入力でサイズ上限エラーを確認したが、公開環境のGlyph Forgeバージョンと上流の詳細なエラー本文は確認していない。標準画像の修正は行っていない。

## 発生した問題

公開サイトで描画文字列に`mojica`、描画に使う文字に`Web`、背景文字に`・`を指定し、標準画像を生成すると、HTTP 422と`IMAGE_SIZE_LIMIT_EXCEEDED`が返った。X背景画像では別の試行で生成に成功した。

## 調査

Mojicaの`GlyphForgeRequestMapper`は標準画像を`/images`、X背景画像を`/images/background`へ振り分ける。`GlyphForgeResponseMapper`は上流の422をサイズ上限エラーに変換するため、Mojicaの応答だけでは上流が返した具体的な理由までは確定できない。

そこで、ローカルのGlyph Forge v1.0.5とv1.0.6のDockerイメージで同じ文字列を使い、標準画像の生成処理と幅を確認した。

| 測定項目 | 値 |
| --- | ---: |
| 文字列から作る元のグリッド | 105 × 42 |
| 描画に使う文字のセル幅 | 22ピクセル |
| 計算上の出力 | 2310 × 924ピクセル |
| 出力幅の上限 | 2048ピクセル |

両バージョンともローカルで`output image width must not exceed 2048`を返した。元のグリッド幅に文字セルの大きさを掛ける処理で、最終画像の幅が制限を超えている。

## 原因と対応

ローカルで確認できた原因は、標準画像のグリッドを拡大した結果が幅制限を超えたことだ。X背景画像は異なる描画経路と固定サイズを使い、今回の試行では成功したため、動画制作にはX背景画像を利用した。これは標準画像の問題を修正したことにはならない。

## 動作確認

- 公開サイト: 標準画像は422、X背景画像は200を観測。
- ローカルDocker: v1.0.5とv1.0.6で同じ幅上限エラーを再現。
- 公開環境のGlyph Forgeの実行バージョンと上流エラー本文: 未確認。

## 再発防止と残る課題

標準画像の制限を緩めるか、自動的に縮小するか、事前に利用者へ説明するかは未決定である。画像寸法の制限には資源消費を抑える役割があるため、解除だけを前提にせず、画質と処理負荷を確認してから検討する。

## 根拠

- Glyph Forgeの`src/glyph_forge/services/output_image_limits.py`と`glyph_art_renderer.py`
- Mojicaの`backend/Mojica.Api/Infrastructure/GlyphForgeRequestMapper.cs`と`GlyphForgeResponseMapper.cs`
- 2026年11月16日の公開サイトおよびローカルDockerでの調査結果
