# 取得元の切り替え後に古い削除エラーが表示された原因と修正

## 結論

削除要求が失敗したとき、エラーを真偽値だけで保持していたため、要求開始後に一覧の取得元が切り替わると、新しい一覧にも古い失敗が表示されていた。エラーに要求元を付け、表示中の取得元と一致する場合にだけ表示する修正を、3件のドラフトPRに分けた。アプリの main には未マージである。

## 発生した問題

### 症状

削除要求を保留したまま一覧の取得元を変更し、新しい一覧を表示した。その後、古い要求を失敗させると、新しい一覧に「削除できませんでした」が表示された。

### 発生条件

- 対象: profile-hub の React 管理画面
- 作品一覧: 取得関数の参照が変わる場合
- スキル・お気に入り一覧: session prop のオブジェクト参照が変わる場合

### 影響

表示中の一覧に対する操作が失敗したかのように見え、利用者が現在の状態を誤解する可能性があった。

## 調査

### 削除要求の完了順序を確認する

削除の応答をテストで保留し、新しい取得元を描画してから古い要求を失敗させた。修正前の各テストでは、新しい一覧に古いエラーが存在することを観測した。成功時の一覧更新には取得元の照合がある一方、失敗時の表示は取得元を保持していなかった。

## 原因

削除失敗の状態が真偽値のみだった。非同期処理が後から失敗すると、どの取得元で開始された処理かを表示側で区別できなかった。

## 解決方法

[#299](https://github.com/kishimin-ai-create/profile-hub/pull/299) では作品一覧の取得関数、[#300](https://github.com/kishimin-ai-create/profile-hub/pull/300) と [#301](https://github.com/kishimin-ai-create/profile-hub/pull/301) では session prop の参照をエラーに関連付け、現在の参照と一致するときだけ表示した。

## 動作確認

各対象テストは修正前に古いエラーを検出し、修正後に成功した。作品12件、スキル13件、お気に入り14件が対象ファイル単位で通過した。

作品の初回実行では forks ワーカーがテスト開始前にタイムアウトし、threads で再実行した。タイムアウトの原因自体は特定していない。

## 再発防止

保留中の削除要求を失敗させるタイミングをテストで制御し、取得元変更後に古いエラーが出ないことを回帰テストにした。

## まとめ

- 異なる取得元へ切り替わった後も、古い非同期処理は完了し得る。
- 削除エラーに取得元を関連付け、現在の参照と一致する場合だけ表示する。
- 初稿時は同一 session オブジェクト内のトークン変更と並べ替えエラーを修正・検証していなかった。

---

## 追記: 並べ替えエラーにも同じ問題があった

初稿の後、[PR #302](https://github.com/kishimin-ai-create/profile-hub/pull/302)、[#303](https://github.com/kishimin-ai-create/profile-hub/pull/303)、[#304](https://github.com/kishimin-ai-create/profile-hub/pull/304) で、作品・スキル・お気に入りの並べ替え失敗も同様に取得元へ関連付けた。いずれもドラフトPRで、アプリの main には未マージである。

各テストで旧取得元の並べ替え応答を保留し、新しい一覧を表示してから旧要求を失敗させた。修正前は新しい一覧にエラーが表示され、修正後は表示されなかった。対象ファイルのテストは作品13件、スキル14件、お気に入り15件が成功した。

ここで確認したのは取得関数または session prop の参照を切り替えるケースである。この時点では、同一 session オブジェクト内でトークンだけが変わるケースと、同じ取得元の参照へ戻るケースは未検証だった。

---

## 追記: 元の参照へ戻ると古いエラーが再表示された

続いて、旧要求が別の取得元を表示中に失敗した後、元の取得関数または session prop の参照へ戻すケースを確認した。エラーに付けた参照が再び一致するため、古い削除・並べ替えエラーが再表示された。3画面それぞれで修正前にテストが失敗した。

[PR #305](https://github.com/kishimin-ai-create/profile-hub/pull/305)、[#306](https://github.com/kishimin-ai-create/profile-hub/pull/306)、[#307](https://github.com/kishimin-ai-create/profile-hub/pull/307) では、取得ライフサイクルが終了した後に返った操作失敗を保持しないようにした。削除と並べ替えの既存テストを拡張し、元の参照に戻した後もエラーが現れないことを確認した。対象ファイルのテストは作品13件、スキル14件、お気に入り15件が成功した。

確認したのは、取得元を切り替えた後に旧要求が失敗し、その後元の参照へ戻る順序である。切り替え前に確定していたエラー、遅れて届く成功応答、同一 session オブジェクト内のトークン更新は今回の検証範囲外。PRはドラフトで、アプリの main には未マージである。
