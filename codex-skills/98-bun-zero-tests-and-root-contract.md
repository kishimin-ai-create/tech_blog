# Bunの終了コード0とテスト実行件数を分けて確認する

## はじめに

テストコマンドを追加しただけでは、APIの振る舞いを検証したことにならない。Bun 1.3.13で観測した「ファイルなし」「空のファイル」「テスト1件」の違いを記録する。

## 前提・環境

Windows、Bun 1.3.13、Hono 4.13.13。`app/backend` で `bun test` を実行した。根拠は `813bc08`、`7765f95`、`d763ba7`。

## やってみた結果

| 状態 | 結果 | 確認できたこと |
| --- | --- | --- |
| テストファイルなし | 終了コード1、No tests found! | テストを検出できない |
| 空のindex.test.ts | 終了コード0、0 pass / 0 fail | APIの確認は0件 |
| GET / のテスト追加 | 1 pass / 0 fail | ルートがHTTP 200を返す |

## 実装・検証

### HTTPの結果を固定する

```ts
import { describe, expect, test } from "bun:test";
import app from ".";

describe("エントリーポイントのテスト", () => {
  test("/にアクセスすると、200である", async () => {
    const response = await app.request("/", { method: "GET" });
    expect(response.status).toBe(200);
  });
});
```

サーバーを起動せず、Honoアプリへのリクエストでステータスを確認した。10月7日の再実行でも1件成功した。

### 整形の確認

`bun run code` は最初、import順序とインデントを指摘した。`bun run code:fix` 後に再実行して成功を確認した。

## つまずいたところ

空のファイルを追加するとコマンドは成功したが、実行件数は0件だった。終了コードだけを報告すると、APIを検証したと誤解される。
