# セッション期限切れ時の読み取りと書き込みを分ける

管理画面のアクセストークンが期限切れになったとき、読み取りと書き込みを同じ方法で再試行すると、書き込みが重複する可能性を考慮する必要がある。profile-hub では、読み取りは復元後に一度だけ再試行し、書き込みは自動再送しない。

## 実装

[PR #141](https://github.com/kishimin-ai-create/profile-hub/pull/141) は、Portfolio の GET が 401 を受け取り、その要求時のトークンがまだ現在のものなら、セッションを復元して新しいトークンで一度だけ再試行する。要求中にセッションが変わった場合は古い要求を自動復元しない。

[PR #142](https://github.com/kishimin-ai-create/profile-hub/pull/142) は、書き込みが 401 になった場合もセッションを復元するが、元の書き込みは送信し直さない。フォームは入力を保持し、利用者にもう一度保存するよう案内する。復元そのものが失敗した場合はエラーを伝える。

## 検証と限界

テストでは GET の復元と再試行、途中でセッションが変わった場合、書き込みの自動再送がないことを確認した。MSW を使ったフォームのテストでは、最初の書き込みが 401、復元後の明示的な再保存が成功し、入力が保持されることを確認した。

これは実ブラウザーの Cookie ポリシーや複数タブの同時更新を検証した結果ではない。これらの PR は積み重ねた開発ブランチ上にあり、本番公開を意味しない。
