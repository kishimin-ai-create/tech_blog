# 通信待ち中の再試行を重ねない

## 結論

公開データの再取得がオフラインで待機している間、再試行ボタンを無効にした。復帰後は待機中のクエリーが再開する。[PR #265](https://github.com/kishimin-ai-create/profile-hub/pull/265)はドラフトで、アプリのmainには未マージである。

## 問題

データの更新に失敗し、再試行を押した後に通信が利用できない場合、クエリーは`paused`になる。以前の画面は`fetching`だけを再試行中と扱っていたため、通信待ちでも再試行を繰り返せた。

## 対応

TanStack Queryの`fetchStatus`が`idle`以外の場合は、再試行ボタンを無効にする。画面には待機中の状態を表示し、既に表示しているデータは維持する。オフライン保存や接続方式は追加していない。

## 検証

実際のQueryClientを使ったテストで、正常取得、更新失敗、オフラインでの再試行、オンライン復帰を順に再現した。待機中はボタンが無効になり、復帰後に更新データが表示されることを確認した。

公開画面の全73テスト、型チェック、Lint、markup lint、整形チェックは成功した。実ブラウザーでのネットワーク切断とスクリーンリーダー実機は未確認である。

## 学び

再試行中かどうかを「通信中」だけで判定すると、通信できるまで保留された操作を見落とす。状態を表示するときは、操作がまだ完了していない待機状態も扱う。
