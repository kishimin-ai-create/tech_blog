# 描画レイアウトの都合を公開APIから外す

## はじめに

画像生成APIには、当初`max_chars_per_line`や`frame_cell_padding_ratio`のような描画調整値があった。しかし一般公開するAPIとして考えると、これらは利用者が決める入力というより、レンダラー内部の都合に近い。

Glyph Forgeでは両方を公開リクエストから削除した。

## `max_chars_per_line`が入力エラーを生んだ

折り返し幅を利用者に指定させると、フレーム文字列より大きい値を送った場合にどうするかという関係制約が必要になる。短い文字列に対して大きな値を指定しただけで、画像としては生成可能なのにAPIがエラーを返す状態にもなり得る。

今回、通常画像のフレームはレンダラー内部で5文字ごとに折り返す方針へ戻した。Xアイコンや背景画像は、キャンバス比率に合わせる既存のレイアウト計算を使う。

利用者は「何を描くか」を指定し、サーバーは「どう配置するか」を引き受ける。責務が明確になり、Swagger UIからも不要な調整項目が消えた。

## 互換性のない入力は黙って捨てない

削除した項目を単にモデルから外すだけでは、Pydanticの設定次第で未知のフィールドが無視される。するとクライアントは、指定が効いていないことに気づきにくい。

そこでリクエストモデルを追加フィールド禁止にし、旧項目を送った場合は`422`を返すようにした。これは破壊的変更だが、無効な指定を成功扱いするより挙動が明確になる。

## 公開パラメータは保守対象になる

公開したパラメータには、入力検証、ドキュメント、互換性、負荷上限、テストが付いて回る。実装の微調整にしか使わない値まで外へ出すと、内部アルゴリズムを変更しづらくなる。

API設計では「設定できるから公開する」のではなく、「利用者の要求として長期的に支える値か」を基準にした方がよい。今回の変更は、公開契約を小さく保つための整理だった。
