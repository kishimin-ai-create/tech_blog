# blogとdiaryをGit履歴から外した話

## はじめに

今回の作業では、`blog/` と `diary/` をコミット履歴から削除した。

理由は、作業記録や記事をローカル成果物として扱い、プロダクトの履歴から切り離すためだ。コードの変更履歴と、作業中の説明文や日誌が混ざると、レビューや履歴追跡がしづらくなる。

## 何を消したか

対象は `blog/` と `diary/` 以下のファイル履歴だ。

履歴を書き換えて、これらのパスが現在のブランチやタグの履歴に残らないようにした。

また、日本語のコミットメッセージも英語へ変更した。

例:

- `fix: 未使用インポートを削除`
- `fix: remove unused imports`

## なぜ履歴を書き換えるのか

単に最新コミットでファイルを削除しても、過去のコミットには残る。

「履歴から削除したい」という要件では、通常の削除コミットでは足りない。そのため、履歴自体を書き換える必要がある。

今回の作業では、`git filter-repo` を使って対象パスを履歴から除去した。

## つまずいたところ

履歴を書き換えるとコミットハッシュが変わる。

そのため、リモートへ反映するにはforce pushが必要になる。保護ブランチではforce pushが拒否されることもある。

実際に、feature系ブランチやタグは更新できたが、保護された `main` ブランチはforce pushできなかった。

## まとめ

blogやdiaryは便利だが、プロダクト履歴に含めるかどうかは分けて考えたい。

今回は、コード変更の履歴を読みやすく保つため、説明記事や作業日誌を履歴から外した。今後も、コミットするものとローカルに残すものを明確に分けるのがよさそうだ。
