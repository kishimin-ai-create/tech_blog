# リリースタグは前に進める

リリース済みの `v2.0.0` があるなら、次の変更は `v2.0.1` にする。

今回いったん `v2.0.0` を新しいコミットへ動かしてしまった。
でも、それはリリース済みタグの意味を変えてしまう。

正しい整理はこうだった。

- `v2.0.0` は元のリリースコミットに戻す
- 新しい README と workflow の変更は `v2.0.1` に載せる
- 新しいタグの GitHub Actions が通ることを確認する

タグはただの名前ではなく、リリースの記録でもある。

既に公開した番号を変えるより、新しい番号を作るほうが読み手にやさしい。
