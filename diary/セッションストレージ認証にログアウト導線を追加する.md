# セッションストレージ認証にログアウト導線を追加する

## 対象読者

- Next.js のクライアント側で簡易的な管理者セッションを扱っている人
- `sessionStorage` に保存したトークンの UI 反映をテストしたい人
- ログインだけ実装してログアウト導線を忘れがちな画面を見直したい人

## 問題

日記アプリには `clearAccessToken` があり、保存済みのアクセストークンを消す処理自体は存在していた。

しかし、ヘッダーからその処理を呼ぶ UI がなかった。管理者としてログインしたあと、ユーザーはアプリ上で明示的にログアウトできなかった。

## 原因

`frontend/app/providers.tsx` のヘッダーは、常にログインリンクを表示していた。

一方で、認証状態は `useAccessToken` で購読できるようになっていた。つまり、状態を読む仕組みとトークンを消す処理はあったが、アプリシェルに接続されていなかった。

## 対応

`SiteFrame` で `useAccessToken` を読み、トークンがある場合は「ログアウト」ボタンを表示するようにした。

ログアウトボタンを押すと `clearAccessToken` を呼び出し、タブ単位の `sessionStorage` からアクセストークンを削除する。

対象ファイル:

- `frontend/app/providers.tsx`
- `frontend/app/providers.small.test.tsx`

## テスト

`frontend/app/providers.small.test.tsx` に、次の振る舞いを追加した。

- トークンがある状態でアプリシェルを描画する
- 「ログアウト」ボタンをクリックする
- `readAccessToken()` が `null` になる
- ヘッダーにログインリンクが戻る

UI とストレージ状態の両方を確認することで、単にボタンが表示されるだけでなく、セッション終了として機能することを固定した。

## まとめ

認証では、ログイン成功だけでなく、ユーザーが自分でセッションを終えられる導線も必要になる。既存の認証ストレージ関数をアプリシェルへ接続するだけでも、利用者にとっては大きな操作性の改善になる。
