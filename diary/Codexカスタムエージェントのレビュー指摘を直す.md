# Codexカスタムエージェントのレビュー指摘を直す

## 対象読者

- Codex のプロジェクトスコープ設定をリポジトリで管理している人
- `.codex/agents/*.toml` や `AGENTS.md` のようなエージェント向け設定をレビューしている人
- 文字コードやドキュメントパスの小さなずれで、開発支援ツールが壊れる問題を避けたい人

## この記事で扱うこと

この記事では、`review/20260621.md` に記録された Codex エージェント設定まわりのレビュー指摘に対して、どの問題を確認し、どう直したかをまとめます。

対象は次の 3 点です。

- `.codex/agents/*.toml` に混入した UTF-8 BOM
- 実在しない `docs/requirements/` への参照
- `CodeReviewAgent` のレビュー反応テンプレートに入った mojibake

アプリケーション本体の機能変更や UI 変更は扱いません。

## 背景

今回の変更は、Codex 用のプロジェクトカスタマイズを共有リポジトリに置く流れの中で発生したレビュー対応です。

レビューでは、エージェント定義そのものは追加されているものの、生成物や参照先にいくつか実運用上の問題があると指摘されました。どれもコード量としては小さいものですが、放置すると Codex の補助機能が読み込めなかったり、将来のエージェント作業が誤ったドキュメントを参照したりします。

## 問題 1: TOML の先頭に UTF-8 BOM が入っていた

`.codex/agents/*.toml` は Codex カスタムエージェントの定義ファイルです。レビューでは、これらのファイルが `name` から始まらず、先頭に UTF-8 BOM の `EF BB BF` を含んでいることが指摘されました。

TOML パーサーによっては、この BOM を有効な文として扱わず、1 行目 1 文字目で `Invalid statement` のようなエラーになります。つまり、ファイルの内容が見た目には正しくても、機械的には読み込めない状態でした。

対応として、すべての `.codex/agents/*.toml` から BOM を取り除きました。修正後は Python の `tomllib` で全ファイルを parse できることを確認しています。

## 問題 2: 要件ディレクトリの参照先が実態とずれていた

ルートの `AGENTS.md` と `docs/AGENTS.md` は、要件の参照先として `docs/requirements/` を案内していました。

しかし、実際にリポジトリに存在する要件ディレクトリは `docs/v1/requirements/` です。このままだと、今後のエージェント作業が「要件が存在しない」と判断したり、プロダクトの振る舞いの根拠を見落としたりする可能性があります。

そこで、該当する instruction の参照先を `docs/v1/requirements/` に揃えました。修正後は、対象の instruction パスから古い `docs/requirements` 参照が消えていることを検索で確認しています。

## 問題 3: レビュー反応テンプレートが mojibake していた

`.github/agents/CodeReviewAgent.agent.md` のレビュー出力テンプレートには、レビューコメント末尾の反応プロンプトがあります。

ここが本来の `Useful? React with 👍 / 👎.` ではなく、`総 / 綜` のような読めない文字列になっていました。このテンプレートをそのまま使うと、今後生成されるレビューにも壊れた文字が混ざります。

対応として、`CodeReviewAgent` の P1 / P2 / P3 の各テンプレート例にある反応プロンプトを `👍 / 👎` に戻しました。

## レビュー応答も残す

修正だけでなく、`review/responses/20260621-responses.md` に各指摘への回答も残しました。

回答では、各 finding について次を明記しています。

- 指摘を再現または確認できたこと
- どのファイルを直したか
- どの検証を行ったか

これにより、レビュー指摘と対応結果を同じリポジトリ内で追跡できます。

## 検証したこと

今回の変更では、アプリケーション本体のテストではなく、レビュー指摘に対応した最小限の検証を行いました。

- `.codex/agents/*.toml` を Python `tomllib` で parse
- TOML ファイルの先頭が `name =` で始まることを確認
- instruction 内の古い `docs/requirements` 参照が残っていないことを確認
- `CodeReviewAgent` テンプレートから壊れた反応 placeholder が消えたことを確認

## まとめ

今回のレビュー対応は、アプリの挙動を変えるものではありません。ただし、Codex エージェントをリポジトリで共有して使うためには重要な修正でした。

小さな文字コードの混入やドキュメントパスのずれでも、エージェントは簡単に誤動作します。設定ファイルをレビューするときは、見た目の Markdown や TOML だけでなく、実際にパーサーで読めるか、参照先が存在するか、テンプレートが次回生成物に悪影響を与えないかまで確認すると安心です。
