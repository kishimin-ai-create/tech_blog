# Next APIプロキシでJSONが途中で切れる問題を直す

## エラー概要

日記一覧 API は 200 を返しているのに、画面では「まだ日記がありません」と表示された。

公開フロントエンドの `/api/diaries` を確認すると、レスポンス本文が JSON として parse できず、`Unterminated string` になっていた。一方で、バックエンドを直接呼び出すと正常な JSON が返っていた。

## 原因

フロントエンドの API プロキシは、バックエンドの `Response.body` とヘッダーをほぼそのまま Next.js の `Response` に渡していた。

このとき、`content-encoding` や `content-length` のようなレスポンスフレーミングに関わるヘッダーまで引き継ぐと、デプロイ環境で本文が途中で切れる可能性があった。

その結果、React Query は日記一覧の JSON を正常に読めず、UI 側ではデータなしの状態に落ちていた。

## 対応

`frontend/app/api/proxy.ts` で次の対応を行った。

- `content-encoding` をプロキシレスポンスから除外
- `content-length` をプロキシレスポンスから除外
- バックエンドレスポンスの body を `arrayBuffer()` で読み切ってから返す

再現テストは `frontend/app/api/proxy.small.test.ts` に追加した。

## 実装上のポイント

API プロキシでは、hop-by-hop header だけでなく、ランタイムや CDN が再計算すべき本文関連ヘッダーも慎重に扱う必要がある。

今回の修正では、アプリ側でレスポンス本文を加工しているわけではない。ただし、Next.js の Route Handler から返す前に body を読み切り、古い本文長や圧縮情報を持ち越さないようにした。

## まとめ

API が 200 でも、レスポンス本文が壊れていれば UI ではデータがないように見える。バックエンド直叩きとフロントエンドプロキシ経由のレスポンスを比較すると、問題がプロキシ層にあることを切り分けやすい。
