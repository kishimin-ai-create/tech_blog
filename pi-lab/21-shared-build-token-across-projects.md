# 新規プロジェクトの設定画面に、別プロジェクト名のビルドトークンが表示された

## はじめに

`email_routing_account_rule_read`・`email_routing_rule_write`という権限は、名前からしてメール転送機能に関するものであり、静的サイトのビルド・デプロイには関係しないと考えられる。実際、この警告を無視してデプロイを進めても、後述の通り別の原因（`_redirects`の無限ループ）でビルドは失敗したが、この権限不足自体がエラーの原因になった形跡はなかった。ただし、これも「エラーメッセージに権限不足が明示的に含まれていなかった」という消去法的な確認であり、権限不足がおよそ無関係であることを公式ドキュメントで裏付けたわけではない。

## 結論

Cloudflare Workers Buildsで新しいプロジェクト（pi-lab）をGitHub連携で作成したところ、詳細設定に表示されたビルドトークンの名前が、以前作成した別プロジェクト（`tdd-todo-app`）のものだった。これは新規プロジェクトの設定ミスではなく、同一Cloudflareアカウント内でGitHub連携用のトークンが使い回される仕組みによるものと考えられる（ただし、この仕組み自体を公式ドキュメントの該当記述で直接確認したわけではなく、観察に基づく推測である）。

## 観察した内容

pi-labのセットアップ画面の「詳細設定」を開くと、次のような情報が表示された。

```json
{
  "build_token_uuid": "40346e80-0b6d-4693-8b74-0cf5dcb6f648",
  "build_token_name": "tdd-todo-app build token",
  "cloudflare_token_id": "5f49c1ec3729cf53b2b39b1411fb50b5",
  "owner_type": "user"
}
```

加えて、次の警告も表示されていた。

> Note: This API token is missing the following permissions: `email_routing_account_rule_read`, `email_routing_rule_write`. If needed, update your API Tokens.

`tdd-todo-app`は、pi-labとは別に以前作成したプロジェクトである。今回セットアップしているのはpi-labなのに、なぜ別プロジェクト名のトークンが出てくるのか、という点が最初は分からなかった。

## 考えられる理由（未確認）

CloudflareのWorkers Builds（GitHub App経由のGit連携）は、GitHub App自体はGitHubアカウント単位でインストールされ、Cloudflare側のビルドトークンもアカウント単位で発行・共有される設計になっていると考えられる。そのため、最初に`tdd-todo-app`のセットアップ時に作られたビルドトークンが、同じCloudflareアカウントで新しく連携するpi-labでもそのまま使われている、という理解が最も筋が通る。

ただし、これは画面の観察と一般的なOAuth連携の仕組みからの推測であり、Cloudflare公式ドキュメントの中でこの「ビルドトークンがプロジェクト横断でアカウント単位で共有される」という仕様を明記した記述を、この調査の中では見つけられていない。

## 権限不足の警告について

`email_routing_account_rule_read`・`email_routing_rule_write`という権限は、名前からしてメール転送機能に関するものであり、静的サイトのビルド・デプロイには関係しないと考えられる。実際、この警告を無視してデプロイを進めても、後述の通り別の原因（`_redirects`の無限ループ）でビルドは失敗したが、この権限不足自体がエラーの原因になった形跡はなかった。ただし、これも「エラーメッセージに権限不足が明示的に含まれていなかった」という消去法的な確認であり、権限不足がおよそ無関係であることを公式ドキュメントで裏付けたわけではない。

## 学び

- Cloudflareのようなアカウント単位でGitHub連携を行うサービスでは、新規プロジェクトのセットアップ画面に、一見無関係な別プロジェクトの名前が表示されることがある。これは連携が壊れているサインとは限らず、認証・トークンがアカウント単位で共有される設計の結果であり得る。
- 権限不足の警告が出ても、警告の対象機能（この場合はメール転送）が今回の用途（静的サイトのデプロイ）と無関係であれば、ひとまず無視して進めて問題ないことが多い。ただし、これは個別に判断すべきであり、常に無視してよいわけではない。

## 未確認事項

- ビルドトークンがCloudflareアカウント単位で共有される、という理解そのものが、公式ドキュメントで直接確認できていない。
- `email_routing`関連の権限不足が、今回のデプロイに一切影響しなかったことも、エラーメッセージに現れなかったことからの消去法的な確認にとどまる。
