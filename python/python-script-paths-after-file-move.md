# Pythonのファイル移動後も設定と出力のパスを保つ

## 結論

補助モジュールやアセットを別ディレクトリへ移すとき、現在の作業ディレクトリを基準にしたパスは実行場所で変わる。起動用スクリプトと各モジュールの`__file__`から基準ディレクトリを決め、テストで設定・フォント・出力先を確認した。

## 背景

小さなPythonスクリプトに取得、解析、画像生成、設定読み込み、テストを追加すると、ファイルを1か所へ置き続けると役割を追いにくくなる。一方で、移動後に`.env`、フォント、生成画像の場所まで変わると、既存の起動方法に影響する。

## 方針

起動用スクリプトはサービス直下に置き、補助モジュールをパッケージ、テストを専用ディレクトリ、フォントとライセンスをアセット用ディレクトリへ移した。設定ファイルと画像出力ディレクトリは従来のサービス直下に保った。

```python
service_dir = Path(__file__).resolve().parent
output_dir = service_dir / "output"
font_path = service_dir / "analysis" / "assets" / "font.ttf"
```

補助モジュール側では、`__file__`から親をたどってサービス直下の設定ファイルを参照する。相対パスを作業ディレクトリにそのまま足す方法は採らない。

## 検証

テストでは、設定ファイルの読み込み先、フォントパス、画像の保存先とファイル名を固定値で確認した。移動後もテスト一式、整形チェック、Pythonのコンパイルが成功した。補助モジュールをサービス直下から import できることも確認した。

実際の外部APIを使った起動は未確認である。したがって、テスト結果だけで運用環境での一連の実行成功までは主張しない。

## 学び

ファイル移動では、ソースだけでなく設定と成果物の「基準ディレクトリ」を先に決める。移動後のテストは import の成否だけでなく、実際に渡すパス値まで見ると、配置の意図を残せる。
