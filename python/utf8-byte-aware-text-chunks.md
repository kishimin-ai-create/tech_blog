# 日本語テキストをUTF-8のバイト数で分割する

## はじめに

文字数とUTF-8のバイト数は一致しない。日本語や絵文字を含む長文を、入力サイズの上限がある処理へ渡すときは、分割片をバイト数で確認する必要がある。ここでは、実際に作成してテストした分割処理の要点を示す。

## 完成形

分割後の各片が指定したバイト上限以下になり、順につなぐと元の文章へ戻る。文字の途中では切らず、上限までに文末記号があればその位置を優先する。

## 前提条件

- Python 3.12以上
- 入力はPythonの`str`で、サイズはUTF-8へのエンコード結果で判定する

## Implementation

### Step 1: 文字ごとのバイト数を数える

1文字ずつ処理し、次の文字を追加すると上限を超える時点で片を閉じる。1文字だけで上限を超える場合は、空の片を作らずエラーにする。

```python
character_bytes = len(character.encode("utf-8"))
if character_bytes > max_bytes:
    raise ValueError("max_bytes is smaller than a character's UTF-8 size")
if chunk_bytes + character_bytes > max_bytes:
    break
```

この単位なら、Pythonの`str`に含まれる各コードポイントのエンコード結果を途中で分断しない。ただし、結合文字や複数コードポイントで構成される絵文字を、画面上の1文字単位で保つことまでは保証しない。

### Step 2: 文の境界を優先する

現在の片の範囲内で最後に見つけた文末記号の位置を記録する。上限より前で切る必要があるとき、その位置を採用する。文末記号がなければ、上限内で収まる最後の文字までを使う。

この方針では、各片の自然さとサイズ制約を両立できる。ただし、文末記号を含まない長文は文字の境界で分割される。

## 動作確認

実装のテストでは、日本語と絵文字が混在する文字列について次を確認した。

- `"".join(chunks) == text`
- 各片の`len(chunk.encode("utf-8"))`が指定上限以下
- 複数バイトの文字が分断されない
- 上限内の文末記号を優先する
- 1文字も収められない上限と、正でない上限を拒否する

分割処理を含むテスト一式は成功した。実際の外部データを使った解析器の限界値は、このテストでは測定していない。

## まとめ

サイズ制限がバイト単位なら、文字数ではなくエンコード後の長さを基準にする。検証では「各片が上限内」に加え、「再連結で原文を復元できる」を対にして確認する。
